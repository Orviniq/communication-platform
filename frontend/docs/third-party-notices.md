# Third-party notices

Every component this project distributes inside the Android artifact, the licence it is
under, and the notice that licence requires. Recorded by ADR-054.

**This document travels with the artifact.** The deployment is a private handover of a
directly installed APK to a known set of people (ADR-044); Apache-2.0 §4 and the BSD
3-Clause licence both require that a recipient of a binary receives the licence text and
the attribution notices, and this file is how that happens. Hand it over with the
installation instructions. It is not a substitute for an in-app notices screen, which is
recorded as follow-up F2 in ADR-054.

## What is covered, and what is not

| Half of the artifact | Where its notices are | State |
|---|---|---|
| Dart packages, the Flutter framework and the Flutter engine, including the SQLCipher and SQLite C sources | `assets/flutter_assets/NOTICES.Z` **inside the APK**, generated by the Flutter tool | Complete and machine-generated. Present in the artifact; nothing in the application displays it (ADR-054 follow-up F2) |
| Android libraries resolved by Gradle | **This document**, below | Complete for the 93 modules a distributed build links, each under its own licence. None of them ships a licence file inside the artifact except `androidx.core`, so nothing else carries them |
| `flutter_webrtc`'s own Android code, compiled into the application rather than linked as a module | Its MIT licence is in `NOTICES.Z`; the two attributions its `NOTICE` file adds are in **this document**, below | Complete (ADR-078) |
| The third-party libraries compiled into libwebrtc's `libjingle_peerconnection_so.so` (BoringSSL, libsrtp, Opus, libvpx, libaom, dav1d, libyuv, abseil-cpp and others) | Nowhere yet: the AAR carries no licence file, and the publisher's aggregated list is for an older build | **Not aggregated here.** WebRTC's own licence is below; ADR-078 follow-up F1 is to generate the list for this build |
| The shared Rust cryptographic core and its vendored C (libsodium, mlkem-native, and the pinned crates) | Per-crate, in `native/crypto_core/Cargo.toml`, `native/crypto_core/vendor/*/LICENSE` and the vendored provenance records | **Not aggregated here.** ADR-032, ADR-036 and ADR-040 pin them; ADR-054 follow-up F3 is to bring them into this document |

To read the machine-generated half out of a built artifact:

```sh
unzip -p app-production-release.apk assets/flutter_assets/NOTICES.Z |
  python -c "import sys,zlib; sys.stdout.write(zlib.decompress(sys.stdin.buffer.read(), 16+zlib.MAX_WBITS).decode())"
```

## Keeping this true

- A change to `android/app/gradle.lockfile` changes the list above. Regenerate both
  together.
- A new direct Dart dependency changes `NOTICES.Z` automatically; nothing here needs
  editing, but the licence still needs reading before the dependency is accepted.
- The Flutter tool builds `NOTICES.Z` from each package's `NOTICES` file, or from its
  `LICENSE` file when there is none; a file named `NOTICE`, which is what
  `flutter_webrtc` ships, is never read. Attributions a plugin keeps there for code
  compiled into the artifact have to be copied here.
- `docs/deployment-and-release.md` step 10 requires this document to be part of the
  handover. A release that skips it is a distribution without its notices.
